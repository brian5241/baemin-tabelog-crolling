# 집 PC 작업 인계

## 1. 사용자 의도와 작업 원칙

- 최종 목적: 업체 정보를 수집하여 Excel(.xlsx)로 저장.
- 대상은 배달의민족. 지역·업종·수량은 아직 정하지 않음.
- 소량부터 단계적으로 늘리기. 최초 대상은 BHC 후곡성저점.
- 여러 화면의 정보를 같은 가게로 합쳐도 됨. 메뉴는 일부만 확인한 상태.
- 사용자에게 존댓말 사용.
- 앞으로의 GitHub 푸시는 요청 시 묶어서 처리. 이번 인계 저장소 생성·푸시는 명시적으로 요청받음.
- 데이터 열람 가능성과 자동 수집 허용 여부는 별개. 배민 자동 수집 약관은 원문 확인이 완료되지 않았음. 개인용·소량이라는 이유로 허용된다고 단정하지 말 것.

## 2. 실제 확인된 사실

### 배민 웹 접근

사용자가 제공한 가게 공유 링크:
https://s.baemin.com/vB000NqF0k2SN

PC 앱 내 브라우저에서 위 링크를 열자 https://www.baemin.com/ 소개 홈페이지로 이동했다. 가게 상세, 메뉴, 평점은 나오지 않았다. 해당 브라우저 시도에서 봇 차단 안내는 관찰되지 않았다. 별도의 웹 조회 도구에서도 링크를 읽지 못했으나, 도구 실패만으로 서버의 봇 차단이라고 판단하지 않았다.

이 결과는 해당 PC 환경에서 공유 링크를 통해 가게 상세를 수집하지 못했다는 의미다. 모바일의 모든 동작이나 앱 수집 불가능을 증명하지 않는다.

### 사용자 제공 이미지

가게 첫 화면, 일부 인기 메뉴, 가게정보·원산지 화면의 총 3장을 수동 판독했다. 주소·평점·리뷰 수·메뉴 가격 등을 읽을 수 있었다. 결과는 DATA.md에 있다. 원본 이미지는 저장소에 넣지 않는다.

### 이전 PC 환경 검사

- adb 명령을 PATH에서 찾지 못함.
- 일반적인 두 위치의 adb.exe도 발견하지 못함. 모든 드라이브를 조사한 것은 아님.
- Windows 연결 기기 목록 조회가 접근 거부로 실패함. USB 연결 여부는 미확인.
- 도구 설치, USB 디버깅 설정 변경, 안드로이드 조작은 실행하지 않음.
- 앱 UI 텍스트 추출, OCR 자동화, 자동 탐색, Excel 출력은 미검증.

## 3. 집 PC 준비

1. PC의 OS 및 git, Python, ADB 설치 여부를 확인한다. 이미 있는 도구를 우선 사용한다.
2. 필요하다면 Google 공식 Android SDK Platform-Tools를 설치한다. 다운로드 페이지의 라이선스 동의는 사용자가 확인한다. Android Studio 전체 설치는 필수가 아니다.
3. 사용자가 데이터 전송 가능한 USB 케이블로 본인 안드로이드를 연결한다.
4. 사용자가 개발자 옵션의 USB 디버깅을 켜고, 휴대폰에 표시된 본인 PC의 RSA 인증 요청을 직접 확인·승인한다. 부트로더 잠금 해제, 루팅, OEM 잠금 해제는 필요하지 않다.
5. Platform-Tools 폴더의 PowerShell에서 아래 명령으로 확인한다.

```powershell
.\adb.exe version
.\adb.exe devices -l
```

`device`이면 연결됨, `unauthorized`이면 휴대폰 승인 필요, `offline`이면 연결 상태 확인이 필요하다. 출력의 기기 일련번호를 GitHub에 올리지 않는다. 여러 기기가 있으면 사용자가 지정한 기기를 선택한다.

6. 사용자가 배민 앱에서 BHC 후곡성저점 화면을 직접 연다. 정확한 배달 주소, 알림, 계정·결제 정보가 노출되지 않도록 주의한다.

공식 참고:
- https://developer.android.com/tools/releases/platform-tools
- https://developer.android.com/tools/adb
- https://developer.android.com/studio/run/device

## 4. 첫 검증: 자동 크롤러부터 만들지 말 것

목적은 현재 가게 화면의 텍스트가 UI 계층에 노출되는지 확인하는 것이다. 승인된 기기 연결 환경에서 사용 가능한 정상 UI 검사 도구를 이용한다. 도구 제약이나 권한 제한을 우회하지 않는다.

- 화면의 가게명·평점이 읽히면 사용자가 제공한 샘플과 대조한다.
- 메뉴 화면과 가게 정보 화면을 각각 확인한다.
- 각 결과는 가게 내부 ID로 묶는다. 가게명만으로 다른 지점을 합치지 않는다.
- 텍스트가 노출되지 않으면 허용된 화면 캡처와 OCR 방식을 검토한다. 스크린샷 제한 등 보호 장치는 우회하지 않는다.
- 사용자 제공 이미지 판독 성공과 실제 앱 자동 추출 성공을 구분한다.
- 로그인·위치 권한·CAPTCHA·예상하지 못한 권한 요청이 나오면 사용자에게 상황을 설명한다.
- 주문, 장바구니, 찜, 리뷰, 전화 걸기 등 외부 상태를 변경하는 작업은 범위 밖이다.
- 비공개 API 인증 우회, 인증서 검증 해제, 취약점 악용, 봇 방어 우회는 하지 않는다.

## 5. 확장 및 완료 기준

### 1곳

가게 첫 화면 → 가게 정보 → 메뉴 일부에서 읽은 필드를 대조한다. 값, 수집 시각, 출처 화면, 누락 이유를 기록한다. 성공한 다음에 .xlsx 내보내기를 구현한다.

### 5곳

사용자가 대상 지역 또는 가게 목록을 지정한 다음 수행한다. 중복 업체, 메뉴 중복, 화면 잘림, 알려지지 않은 필드를 검증한다. 가게 정보는 업체 시트, 메뉴는 메뉴 시트에 저장한다.

### 20곳

앞 단계가 안정적이고 이용 조건을 검토한 뒤 진행한다. 수집 시간, 정확도, 누락률, 실패율을 기록한다. 차단·과도한 요청 신호가 있으면 중단한다. 임의의 0.5초 간격이 차단 방지나 이용 허가를 보장하지 않는다.

## 6. 배경: 타베로그와 혼동 금지

이전에는 일본 음식점 소거법 추천 앱을 논의했다. 역 중심점, 평점 하한, 주장르 분류, 정보 없음 유지 등이 논의되었지만 현재 작업은 배민 업체의 Excel 정리다.

타베로그에서는 후쿠오카 랭킹 1페이지와 오사카 기본 목록 2페이지를 읽은 기록이 있다. 오사카는 평점순이 아닌 예약·PR 우선 목록이었으므로 후쿠오카와 직접 비교할 수 없다. 배민 앱 자동 수집 가능성을 증명하는 자료도 아니다. 이 저장소에는 기존 타베로그 소스코드가 없다.

## 7. 종료 및 개인정보 관리

테스트 결과만 로컬에 보관하고 원본 화면·UI 덤프는 기본적으로 커밋하지 않는다. 테스트 후 사용자가 USB 디버깅을 끄고 필요하면 PC 디버깅 승인을 취소한다. 비밀번호·토큰을 채팅이나 저장소에 넣지 않는다. GitHub로 자료를 옮기는 것은 실행 중인 로컬 세션을 클라우드로 이전하는 것과 다르다.
